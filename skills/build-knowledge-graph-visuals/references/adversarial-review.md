## 1. 审查方式

不要以作者身份证明自己做得对。分别扮演四个反方：

- 怀疑型技术编辑：要求证据，拒绝含混因果。
- 第一次学习的读者：只关心能否顺着图理解。
- 面试官：追问机制、边界和指标。
- 移动端设计审查者：只看实际显示尺寸和遮挡。

每次审查都要产生“问题 -> 判断 -> 修正”记录。不能只勾选“通过”。

## 2. 第一性原理审查

先把视觉效果全部拿掉，只看节点表和关系表：

1. 这张图必须解释的唯一核心问题是什么？
2. 哪些节点是回答该问题不可约的最小组成？
3. 哪些关系来自定义、机制或因果，哪些只是同时出现在一章？
4. 哪些节点删除后不影响中心命题？删除它们。
5. 如果颜色全部变灰，关系方向和层级仍然清楚吗？
6. 如果只读强关系，能否复述章节主线？
7. 图谱是否暴露了可验证指标，还是只罗列方法？
8. 图谱是否呈现边界条件和失败方式，还是只呈现“正确答案”？

第一性原理结论只有三种：

- `graph`：交叉关系是理解内容的必要组成。
- `simpler-visual`：流程图、层级图、矩阵或表格更诚实。
- `insufficient-evidence`：原文不足以支持建图，需要补材料或标注推断。

## 3. 内容真实性攻击

逐条攻击强关系：

- 原文在哪里明确支持这条关系？
- 这是相关性、顺序、依赖还是因果？是否被画成了更强的关系？
- 关系是否只在特定条件下成立？条件是否遗漏？
- 节点名称是否偷换了原文概念？
- 英文技术术语、大小写和缩写是否准确？
- 示例中的业务判断是否被误写成通用规律？
- 编辑推断是否标为 `inferred`？
- 每个 `evidence_id` 是否能解析到真实来源和定位，而不是只填了一个看似正式的占位符？

发现证据不足时，按顺序处理：

1. 换成更弱、更准确的关系词。
2. 改为虚线弱关联。
3. 标注推断或边界条件。
4. 删除。

不要用更漂亮的箭头掩盖证据空白。

## 4. 关系必要性攻击

对每条边执行：

- 删除测试：删除后读者是否损失重要判断？
- 反向测试：反向是否同样“说得通”？如果是，关系词不够具体。
- 中介测试：是否缺少一个关键中间节点，导致关系跨度过大？
- 重复测试：是否已经有另一条边表达同一判断？
- 装饰测试：它存在只是为了画面更像网状图吗？

对每个节点执行：

- 孤立测试：没有真实关系的节点删除。
- 目录测试：它是否只是文章标题，而不是知识对象？
- 同义测试：是否与另一个节点重复？
- 获得感测试：读者记住它后能做什么判断？

## 5. 替代结构攻击

主动尝试推翻“必须做知识图谱”的假设：

- 如果主要表达先后顺序，改用流程图。
- 如果主要表达上下级包含，改用树或层级图。
- 如果主要表达方案比较，改用矩阵或表格。
- 如果主要表达时间变化，改用时间线。
- 如果主要表达一个中心和若干同级主题，思维导图可能足够。

只有当多个知识对象之间存在三条以上有学习价值的交叉关系，网状知识图谱才有明显优势。

## 6. 学习价值攻击

从学习闭环审查：

- 图是否回答“为什么”，还是只回答“有什么”？
- 是否从问题连接到机制，而不是把两组节点并排放置？
- 是否从机制连接到指标，告诉读者怎样验证？
- 是否能从核心节点沿强关系走出一条完整复习路径？
- 是否包含典型误区或失败边界？
- 图中的核心判断能否转化为一个面试回答框架？

如果图只能帮助读者记名词，不能帮助做判断，它是术语海报，不是学习型知识图谱。

## 7. 视觉与传播攻击

在实际目标宽度下审查，不看原始大图自我安慰：

- `mobile`：按约 390 CSS px 宽预览。
- `poster`：按课程页面缩略宽度预览，并再检查放大细节。

攻击问题：

- 最小关键文字是否无需缩放即可读？
- 颜色对比是否符合黑底和白底各自环境？
- 是否有文字出框、压线、遮挡或被阴影吃掉？
- 强关系是否一眼可识别？
- 弱关联是否比强关系更抢眼？
- 画面是否因为追求对称而增加无价值节点？
- 读者第一眼是否知道从哪里开始？
- 图例是否真的必要？不用图例能否通过布局和标签理解？

若手机预览失败，先按 `text-budget.md` 压缩重复表达，再拆分独立知识点或将次要细节移入知识清单，必要时拆图并调整布局。禁止缩小字号塞入正文。反查压缩是否损失否定、适用条件、数量含义和风险边界。

## 8. 审查记录模板

在图谱规格末尾追加：

```markdown
## 对抗式审查记录

| 攻击角度 | 发现 | 判断 | 修正 |
|---|---|---|---|
| 内容真实性 |  |  |  |
| 关系必要性 |  |  |  |
| 替代结构 |  |  |  |
| 学习价值 |  |  |  |
| 手机可读性 |  |  |  |

## 残余限制
- <仍需要用户知道的限制>
```

至少写出一个被删除或降级的节点/关系。若一个复杂图谱在对抗审查后“零修改”，通常意味着审查不够认真。
