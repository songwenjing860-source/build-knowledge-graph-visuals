## 1. 从读者任务出发

知识图谱不是文章摘要的装饰版。先定义读者要解决的任务：

- 课前导航：帮助建立章节地图，节点少，主线强。
- 课后复习：覆盖机制、问题、指标和应用，允许更多交叉关系。
- 面试准备：突出“问题 -> 决策 -> 方案 -> 指标 -> 追问”。
- 完整索引：覆盖更全，但必须允许点开或分层阅读。

用一句可判断真假的中心命题约束整张图。例如：

> 高质量知识图谱不是术语集合，而是由证据支撑、可以逐条检查的关系模型。

如果中心句只是“本章介绍知识图谱”，它无法指导关系建模。

## 2. 抽取原子知识对象

先逐篇提取候选对象，再跨文章合并。常用类型：

| 类型 | 识别问题 | 示例 |
|---|---|---|
| 核心对象 | 本章最终解释什么能力或系统？ | 知识图谱 |
| 输入/前提 | 它依赖什么信息？ | 读者任务 |
| 子能力 | 它由哪些不可替代模块构成？ | 实体抽取 |
| 问题 | 什么会导致失败？ | 边界重叠 |
| 机制 | 系统怎样解决问题？ | 关系标注 |
| 约束 | 哪些条件必须或尽量满足？ | 硬约束、软约束 |
| 指标 | 如何验证效果？ | 证据覆盖率 |
| 实践产出 | 如何落到面试或业务表达？ | 简历表达、追问链 |

节点标签遵循：

- 一节点一概念。
- 标题尽量 2-8 个汉字或一个稳定英文术语。
- 副标题只解释“它是什么”，不塞入完整段落。
- 文章标题不是天然节点；只有承担知识语义时才保留。

每个候选节点必须记录来源：文章编号、段落或原句。没有证据的节点标记为 `inferred`，不得伪装成原文结论。

## 3. 归一化与去重

把不同文章中的同义表述合并为一个规范节点：

```text
知识建模 / 内容建模 / 结构化建模
-> 内容建模
```

不要合并相近但不同的概念：

```text
节点 != 关系
相关 != 因果
显示尺寸 != 导出像素
```

判断是否该合并，问：两者的输入、输出、失败方式和衡量指标是否相同？只要有一项关键不同，就保留为独立节点。

## 4. 建立有语义的关系

优先使用可读成句子的关系动词：

| 关系类别 | 推荐动词 |
|---|---|
| 组成 | 包含、由…构成、属于 |
| 顺序 | 前置于、进入、输出到 |
| 依赖 | 依赖、需要、以…为前提 |
| 问题 | 导致、暴露、混淆、阻断 |
| 解决 | 解决、缓解、约束、兜底 |
| 评估 | 衡量、验证、暴露误差 |
| 表达 | 支撑回答、转化为、体现为 |
| 分流 | 路由到、选择、切换到 |

禁用没有信息量的默认词：

- 相关
- 联系
- 影响
- 对应

必须使用时，补充方向和机制。例如把“置信度与澄清相关”改为“低置信度触发澄清”。

关系表至少包含：

```text
source | relation | target | strength | evidence | status
```

其中：

- `strength`：`strong` 或 `weak`。
- `status`：`explicit`、`inferred` 或 `disputed`。
- `evidence`：原文定位或简短依据。

关系验证使用三项测试：

1. 句子测试：`source + relation + target` 是否自然、明确？
2. 反向测试：反向后是否明显错误？如果正反都成立，关系词过于含混。
3. 删除测试：删除这条边会不会损失一个重要判断？不会就删除。

## 5. 排序与删减

为节点计算编辑优先级，不必追求数学精确：

```text
priority = reader_value + structural_value + evidence_strength - duplication_cost - reading_cost
```

每项按 0-2 评分。

- `reader_value`：能否帮助读者理解或回答问题？
- `structural_value`：是否连接多个重要模块？
- `evidence_strength`：是否有明确原文支撑？
- `duplication_cost`：是否与其他节点重复？
- `reading_cost`：是否需要大量文字才能解释？

优先保留高连接度且有证据的节点。不要为了对称硬凑数量。

推荐规模：

| 密度 | 总节点 | 强关系 | 弱关联 | 适用场景 |
|---|---:|---:|---:|---|
| mobile | 10-16 | 6-10 | 0-6 | 手机无需缩放 |
| poster | 18-28 | 8-14 | 6-18 | 点开缩放、课程大图 |

超过 28 个节点时，先考虑拆成总图 + 子图。单图塞满不是“完整”，只是把阅读成本转嫁给用户。

## 6. 图谱规格模板

绘图前创建 `<topic>-graph-spec.md`：

```markdown
# <主题>知识图谱规格

## 读者任务
<看完后能回答的问题>

## 中心命题
<一句可验证的判断>

## 密度与尺寸
- density: mobile | poster
- canvas: 1080x2400 | 1800x2600
- viewing: direct | zoomable

## 节点
| id | label | subtitle | type | priority | source | status |
|---|---|---|---|---:|---|---|

## 关系
| source | relation | target | strength | evidence | status |
|---|---|---|---|---|---|

## 删除项
| candidate | reason |
|---|---|

## 推断声明
<列出并解释 inferred / disputed 关系>
```

## 7. 质量指标

建模完成后检查：

- 中心命题覆盖：核心节点是否共同支撑中心命题？
- 证据覆盖：所有强关系是否有原文证据或明确推断声明？
- 孤立节点：必须为 0；否则删除或补充真实关系。
- 重复节点：必须为 0。
- 装饰边：必须为 0。
- 关系可读性：每条强关系都能读成一句清楚的话。
- 替代结构合理性：如果去掉交叉边仍不损失信息，应改用流程图或层级图。
